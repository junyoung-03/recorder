## 1. 전체 디자인 방향 (v2 컨셉)

- 키워드: **타임라인 / 깔끔 / 카드형 / 여백 넉넉**
- Primary: `#2563EB` 유지
- Secondary 포인트: 민트/라임 계열(`#22C55E`, `#A7F3D0`) 소량 사용
- 카드: 흰색 + 얕은 그림자 또는 얇은 보더
- 랜딩은 밝은 톤(`bg-slate-50`), 내부는 `bg-warm` 사용 중
- 반응형: 데스크탑 2~3열, 모바일 1열

### 1.1 타이포그래피
- H1: 32~40px bold
- H2: 24~28px semibold
- H3: 20~22px semibold
- 본문: 14~16px
- line-height: 1.5~1.7

### 1.2 공통 컴포넌트 스타일
- 버튼
  - Primary: 파란색 꽉 찬 pill
  - Secondary: 흰 배경 + 파란 테두리
  - Ghost/Text: 파란 텍스트 링크
- 카드
  - bg-white, rounded-2xl, border `#E5E7EB`, shadow-sm
- 인풋
  - border `#D1D5DB`, radius 8px

## 2. 공통 앱 레이아웃 v2 (현재 구현)

- 상단: 얇은 헤더 + 보더
- 좌측: 사이드바 `w-64`, 활성 메뉴는 파란색 배경
- 메인: `max-w-6xl` 컨테이너, 카드/리스트 중심

```text
┌───────────────────────────────────────────────┐
│ TopBar: 로고 | 날짜 | 검색 | 프로필            │
├───────────────┬──────────────────────────────┤
│ Sidebar       │ Main Content                  │
└───────────────┴──────────────────────────────┘
```

### Sidebar 스타일
- 배경: 흰색, border-right
- 활성 메뉴: 파란색 배경 + 흰색 텍스트
- 아이콘 없이 텍스트 기반 (현재 구현)

## 3. 공개 랜딩 페이지 스펙 (현재 구현)

### 3.1 섹션 순서
1. 상단 네비
2. Hero
3. 문제 공감
4. 핵심 기능
5. 사용 흐름 (How it works)
6. 화면 미리보기
7. CTA 섹션
8. 푸터

### 3.2 상단 네비
- 링크: 기능 / 화면 미리보기 / 자주 묻는 질문
- 버튼: 로그인(아웃라인), 시작하기(Primary)

### 3.3 Hero
- 헤드라인: "하루의 모든 기록을 한 화면에서 정리하세요"
- 서브: 통합 생활 기록 설명
- 배지: "지금 바로 시작하세요"
- 버튼: 시작하기 / 화면 먼저 구경하기

### 3.4 문제 공감
- 불릿 3~4개
- 마무리 문장: 날짜 중심으로 되돌아볼 수 있게 도와줌

### 3.5 핵심 기능 (6개 카드)
- 가계부 / 일정 / 할 일 / 운동·몸 / 일기 / 친구 소셜

### 3.6 사용 흐름 (3단계)
1) 카테고리 선택  
2) 하루 마감 기록  
3) 주/월 단위 회고

### 3.7 화면 미리보기
- 현재는 빈 상태 목업 박스(아이콘 + "아직 기록이 없어요")
- 카드 텍스트 크기 축소 적용

### 3.8 CTA
- 문구: "지금 바로 시작해 보세요"
- 버튼: 시작하기

## 4. 홈 페이지 v2 (현재 구현)

### 4.1 레이아웃
- 상단 2열: 인사/요약 + 미니 캘린더
- 중단 2열: 오늘 일정 / 오늘 해야 할 일
- 하단 2열: 지출 요약 / 최근 기록

### 4.2 미니 캘린더

## 5. 가계부 / 일정 v2 레이아웃 (현재 구현 기준 유지)

### 5.1 가계부
- 상단 요약 유지
- 상단 2열: 통계/분석 + 빠른 거래 추가
- 하단 탭: 날짜별 / 카테고리별 / 고정비
- 지출=빨강, 수입=파랑, empty state 개선

### 5.2 일정
- 상단: 캘린더
- 선택 날짜 요약 카드
- 하단 2열: 이번 주 해야 할 일 / 이번 달 일정 목록

## 11. 인증/회원가입 (현재 구현)

- Supabase Email OTP 기반
- 회원가입 입력:
  - 구글 이메일(@gmail.com) + 인증코드
  - 아이디, 닉네임(선택), 생년월일, 비밀번호/확인
- 흐름:
  1) OTP 전송 → 2) 코드 확인 → 3) 비밀번호 설정 + `public.users` upsert
- 프로필 완료 조건:
  - `public.users.username` + `public.users.birth_date`가 있어야 로그인 상태로 간주
  - 미완성일 경우 `/register`로 유도 (단, `/`과 `/login`은 예외)
