[1단계: 새로운 개발 멈추기 및 최종 배포]

개발 중단: 더 이상 새로운 기능을 추가하거나 무언가를 만드는 것을 당장 멈춰야 합니다.

최종 배포: 최종 배포를 진행하고 테스트를 완료한 후, 개발 구조에 집중해야 합니다.

[2단계: 스터디 및 프로젝트 회고 작성 (마인드 정리)]

목적 복기: 이 스터디에 왜 들어왔고, 무엇을 하고 싶었으며, 왜 이 주제를 정했는지 기록합니다.

주차별 정리: 몇 주차에 무엇을 했고 어떤 결과가 나왔는지 주차별로 정리합니다.

결과 분석: 처음에 의도했지만 되지 않았던 것과 의도하지 않았는데 된 것을 파악합니다. 계획했던 것들과 얼마나 바뀌었는지 확인합니다.

자체 평가: 프로젝트 중 부딪힌 문제를 어떻게 해결했는지, 내가 잘했다고 생각하는 부분과 아쉬웠던 부분, 느낀 점을 솔직하게 기록합니다.

[3단계: 내 코드의 '이유' 찾기 (구조 및 기술 스택 파악)]

기술 선택 근거: 내가 선택한 기술(TSX, DB, React, SQLAlchemy 등)과 파이썬 프레임워크를 왜 선택하고 써야 하는지 명확한 이유를 정리합니다.

SQLAlchemy 선택 이유: ORM을 왜 쓰는지(생산성, 이식성, 보안, 유지보수)와 단점(성능, 복잡도)을 정리합니다.

파이썬 프레임워크를 쓰는 이유: 라우팅/세션/미들웨어/확장성 등 프레임워크가 제공하는 기본 가치와, 직접 구현했을 때의 비용을 정리합니다.

코드 구조 이유: 현재 내 코드를 왜 이런 구조로 짰는지 설명할 수 있어야 합니다.

프로그램 구조 파악: 현재 프로젝트의 폴더/모듈 구조를 직접 그려보고 역할을 설명합니다.

프론트엔드와 백엔드: 프론트엔드와 백엔드가 어떻게 작동하게 만들어져 있는지 구조를 파악합니다. 꼭 분리를 해야 하는지, 분리하는 것과 안 하는 것의 차이는 무엇인지 확인하고 내 서비스와 비교해 봅니다. 왜 JS와 JSX가 따로 있는지, 왜 한쪽(프론트 또는 백엔드)만 있는지 파악합니다.

왜 JS와 JSX가 분리되는지: 빌드 도구/라우팅/컴포넌트 분리 기준과 가독성 관점에서 정리합니다.

프론트만 있고 백엔드가 없는 이유: 서버리스(Supabase 등) 구조에서 가능한 범위와 한계를 정리합니다.

프론트+백엔드 둘 다 있을 때 장단점: 권한/검증/확장성/개발속도/운영비용 관점에서 비교합니다.

만든 구조 파악: 현재 구조의 실제 동작 흐름을 단계별로 확인합니다.

현재 구조의 장단점 파악: 지금 구조가 유리한 점/불리한 점을 명확히 나열합니다.

여러 사람이 함께 개발하는 상황 고려: 협업 시 필요한 규칙(코드 스타일, 브랜치 전략, PR/리뷰, 문서화)을 정리합니다.

[4단계: 부족한 CS/웹 지식 채우기 (이론 공부)]

웹 통신 기초: Ajax, 통신 구조, HTTP Method (GET, POST 등)를 알아봅니다. 라우팅(Routing) 개념과 렌더링 루트를 확인합니다. Stateless, Request, Response, Cookie 개념과 CORS(백엔드/프론트엔드 구별 규칙)를 공부합니다. 서버 캐싱에 대해 알아봅니다.

Ajax 실제 사용 흐름: 요청-응답 구조와 실패/재시도/에러 처리 패턴을 정리합니다.

서버 캐싱: 캐시 레이어(브라우저/서버/DB) 구분과 TTL/무효화 전략을 정리합니다.

Stateless, Request/Response, Cookie: 상태 유지 방식과 보안 이슈(세션/토큰) 정리합니다.

렌더링 루트: SPA에서 루트 마운트가 어떻게 시작되는지 확인합니다.

라우팅 개념: 클라이언트 라우팅과 서버 라우팅의 차이를 정리합니다.

HTTP Method: 각 메서드의 의도와 실제 사용 예시를 정리합니다.

CORS: 왜 발생하고 어떻게 해결하는지 실제 예시로 정리합니다.

환경변수: 환경변수(.env)는 무엇이며 왜 사용해야 하는지 명확히 이해합니다.

환경변수 관리 규칙: 개발/배포 환경 분리, 노출 위험, 로테이션 기준을 정리합니다.

트렌드 비교: 요즘 개발 구조는 어떤지 찾아보고, 내 서비스의 개발 구조와 비교해 장단점을 파악합니다.

현재 트렌드와 비교: 최신 구조(서버리스/엣지/모놀리스/마이크로서비스 등)와 내 구조를 비교합니다.

SRE 관점 유지보수: 변경 관리, 장애 대응, 모니터링/로깅의 중요성을 정리합니다.

[5단계: 시각화 및 문서화 작업]

웹 서비스 흐름 파악: 웹서비스에 처음 접속했을 때부터 어떻게 진행되는지 파악하고 유저 스토리 보드를 그려봅니다.

동작 메커니즘 도식화: 주요 기능(예: 버튼 동작 루트, 구글 캘린더 연동 등)이 실행될 때 어떤 코드가 어떻게 작동하는지 머메이드(Mermaid)를 활용해 동작 방식으로 그려봅니다.

구조 문서화: 개발 구조에 대해 이해한 내용은 전부 정리해서 한곳에 모아둡니다.

버튼 동작 루트: 클릭 이벤트 → 상태 변경 → API 호출 → 화면 반영까지 흐름을 도식화합니다.

캘린더 연동: 외부 캘린더(구글) 연동/등록 흐름과 공휴일 캘린더 조회 흐름을 정리합니다.

주요 기능별 코드 경로: 기능 하나가 실행될 때 어떤 파일/모듈을 거치는지 맵을 만든다.

[6단계: 문제점 진단 및 향후 개선 계획 세우기]

현재 상태 점검: 현재 내가 만든 구조의 장단점을 파악합니다.

취약점 파악: 현재 내 환경변수(.env) 설정은 어떻게 되어 있으며, 취약점이나 문제점은 없는지 점검합니다.

개선 계획: 구조적 단점이나 문제점을 바탕으로 개선점을 찾고, 무엇을 바꾼다면 어떻게, 왜 바꿀 것인지 명확히 정리합니다.
